# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Site overview

This is a [Middleman](https://middlemanapp.com/) static site (`config.rb`) for cowholio4.com, styled with Tailwind CSS + daisyUI. Blog posts live in `source/blog/` as Markdown (`.html.md`) or Slim (`.html.slim`) files, following the `YYYY-MM-DD-title-slug.html.md` naming convention. The `blog.permalink` pattern is `/blog/:year/:month/:day/:title.html` (see `config.rb`).

Run the dev server with:

```
bundle exec middleman server --bind-address=0.0.0.0 -p 3000
```

## Blog post frontmatter

Every post needs YAML frontmatter with these fields:

```yaml
---
title: Post Title
date: YYYY-MM-DD 00:00 PST
author: Jason Pope
ai_model: Claude Sonnet 5   # only present if AI helped write the post
category: Development
archived: false
description: One-sentence summary for meta tags and previews.
---
```

- `author` — always `Jason Pope`. Every post must have this field.
- `category` — a single category for the post (e.g. `Development`, `Troubleshooting`, `Security`, `AI`). Every post must have this field; reuse an existing category from other posts in `source/blog/` rather than inventing a near-duplicate. Categories are powered by `middleman-blog`'s `custom_collections` (see `config.rb`) and rendered via `category_path` in `source/layouts/blog_layout.slim` and `source/blog.html.slim`; archive pages are generated by `source/category.html.slim`.
- `ai_model` — only add this field if an AI model (e.g. Claude) helped write or substantially edit the post. Use the model's name (e.g. `Claude Sonnet 5`). Omit the field entirely for posts written without AI assistance — don't set it to `none` or blank.
- **When Claude writes or co-authors a new blog post, always add the `ai_model` field with the current model's name.** Both the frontmatter field and the git commit `Co-Authored-By` trailer should be set — they're independent signals and both should stay accurate.
- `archived` marks a post as outdated; the layout renders a warning banner when true.
- The body uses `SPLIT_SUMMARY_BEFORE_THIS` (matching `blog.summary_separator` in `config.rb`) to mark where the index-page summary should be cut off.

The `author` and `ai_model` fields drive both the visible byline (`source/layouts/blog_layout.slim`) and the `schema.org/Person` structured data on each post page — don't hardcode author info in the layout.
